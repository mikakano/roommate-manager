# 合租生活管家

把账算清，把家照顾好。一个面向年轻人合租场景的交互网页，集中管理共同费用、清洁值日、公共物品和室友公约。

**作品入口：[点击体验](https://mikakano.github.io/roommate-manager/)**


## 当前功能

| 模块 | 可体验功能 |
| --- | --- |
| 生活总览 | 我的待结清金额、本月公共费用、今日值日、低库存提醒和最近账单 |
| 费用 AA | 新增、编辑、删除账单；等额、按金额、按整数权重分摊；实时预览；结清与撤销；跨账单抵扣建议 |
| 清洁值日 | 本周与全部任务；新增、编辑、删除、完成与撤销；调整负责人；配置持续轮班、暂停与启用 |
| 公共物品 | 登记、编辑、删除、消耗、补货与库存校准；低库存提醒；每件物品最近10次变动；补货关联采购账单 |
| 室友公约 | 新增、编辑、删除；本地阅读确认与修改建议；最近10个版本及旧版意见 |
| 合租屋管理 | 修改屋名；添加、改名、移出室友；交接未完成任务并保留历史引用 |

首次打开预置“阳光合租屋”和4位室友，顶部可切换室友操作视角。数据保存在当前浏览器，刷新后可继续体验；“恢复演示数据”需确认后执行。
页面已适配电脑与手机屏幕，可在不同设备上查看和操作主要功能。

## 关键设计与实现细节

### 费用：既算得对，也明确谁能修改

费用以整数“分”计算，避免小数误差。100元由3人等额承担时，分摊为33.34、33.33、33.33元，总额保持100元；按金额分摊必须与总额一致，按权重分摊会分配余数。本人垫付的自身份额与零金额份额无需偿还，首页统计包含历史未结清费用。

账单创建人与垫付人分别保存。例如小林创建、小周垫付的账单中，**小陈的待付份额只能由小林或小陈修改状态，小周和小许只能查看该份额**。账单编辑和删除仅限创建人，按钮和操作处理逻辑均检查规则，防止通过其他操作绕过责任限制。

仅修改账单名称、分类或日期时保留结清状态；修改金额或分摊规则时，需要确认重置结清状态。抵扣建议单独计算各人的净应付和净应收，不自动修改原账单，也不触发支付。

### 物品：让每次增减都有依据

每件物品独立保留最近10次有效变动，显示操作室友、完整时间、增减数量、计量单位和前后库存；第11次变动会移除最早一条。消耗不能超过库存，校准需要填写原因，无效或取消的操作不产生记录。

历史记录保存操作时的姓名和单位，后续改名或更改单位不会改写旧记录。升级旧版数据时保留已有库存，旧操作历史保持为空，不补造时间与操作人。补货可同时生成采购账单，删除关联账单不会反向扣减库存。

### 值日与公约：考虑持续使用和修改后的结果

轮班可指定区域、执行星期、起始日期与室友顺序，自动补齐未来4周。重复刷新不会重复生成，手动调整的任务会保留，手动删除的自动任务不会重新出现；修改规则前说明影响范围并要求确认。

公约支持阅读确认和修改建议。内容更新产生新版本并重置新版确认，旧版内容和意见保留，最多保存包含当前版本在内的10个版本。移出室友后，其账单和操作历史仍可查看，未完成任务交接给其他活动室友。

### 交付：控制范围，保留完整体验

全部样式、逻辑与示例数据整合在一个 `index.html` 中，没有外部资源依赖，不需要安装依赖或启动后台。页面提供输入校验、空状态、操作反馈、删除确认、本地保存异常提示和手机布局，让展示与更新更方便。

## 建议体验顺序（约3分钟）

1. **费用规则**：以小林创建100元账单、选择小周垫付。切换小陈可修改自己的结清状态；切换小许则不能修改小陈的份额。切回小林可编辑账单。
2. **物品记录**：以不同室友消耗、补货同一件物品，展开“最近记录”，查看操作人、时间与前后库存；补货时可勾选同时生成采购账单。
3. **持续轮班**：进入清洁值日，展开“持续轮班”，配置执行星期与室友顺序，再到“全部任务”查看未来安排。
4. **公约版本**：先标记一条公约已阅读，再编辑内容，观察新版确认重置与历史版本保留。
5. **保存与恢复**：刷新确认操作仍在；如需重新体验，确认恢复演示数据。
